概述

要投放廣告並賺取收益，需將 Google Mobile Ads Flutter Plugin 整合進 Flutter 應用程式。在請求廣告之前，必須先匯入並初始化外掛。

本規格涵蓋：匯入與初始化 Google Mobile Ads Flutter Plugin，以及選擇廣告格式。

注意：Google Mobile Ads Flutter Plugin 僅支援 Android 與 iOS，不支援 web 與桌面平台。

平台支援

  • 支援：Android、iOS
  • 不支援：Web、桌面平台（Windows / macOS / Linux）

若專案需同時支援 web／桌面，需另行處理廣告策略（例如以條件編譯或平台判斷跳過廣告）。

前置需求

  • Flutter 3.38.1 或更高版本
  • Android：最新版 Android Studio
  • iOS：最新版 Xcode 並啟用命令列工具（詳見 Install Flutter）
  • AdMob 應用程式 ID（App ID）。詳見 Find and copy an app ID or ad unit ID

匯入外掛

請參考 google_mobile_ads（pub.dev）進行匯入。

加入相依

執行以下指令：

$ flutter pub add google_mobile_ads

這會在 pubspec.yaml 加入類似下列的一行（並隱式執行 flutter pub get）：

dependencies:
  google_mobile_ads: ^9.2.0

或在編輯器中執行 flutter pub get。

匯入 Dart 程式碼

在 Dart 程式碼中使用：

import 'package:google_mobile_ads/google_mobile_ads.dart';

設定應用程式

匯入外掛後，選擇平台進行設定：

Android

  1. 在 Android Studio 中開啟 android/app/src/main/AndroidManifest.xml。
  2. 在 <application> 標籤內加入 <meta-data> 標籤：
<manifest>
    <application>
        <!-- 範例 AdMob app ID：ca-app-pub-3940256099942544~3347511713 -->
        <meta-data
            android:name="com.google.android.gms.ads.APPLICATION_ID"
            android:value="ca-app-pub-xxxxxxxxxxxxxxxx~yyyyyyyyyy"/>
    </application>
</manifest>
  • android:name：必須為 com.google.android.gms.ads.APPLICATION_ID
  • android:value：填入 AdMob 應用程式 ID

詳見 Set up Google Mobile Ads SDK (Legacy)。

iOS

  1. 在 Xcode 中開啟 ios/Runner/Info.plist。
  2. 加入 GADApplicationIdentifier 鍵，值為 AdMob 應用程式 ID 字串：
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-################~##########</string>

詳見 Update your Info.plist。

初始化 SDK

載入廣告之前，必須呼叫 MobileAds.instance.initialize() 初始化 Google Mobile Ads Flutter Plugin。

此方法回傳一個 Future，在初始化完成或 30 秒後結束。

// Initialize the Mobile Ads SDK.
MobileAds.instance.initialize();
注意：初始化為非同步；應在請求任何廣告之前完成初始化，並可 await 該 Future 以確保就緒。

Banner 廣告

Banner 廣告佔據應用程式佈局中的某個位置，通常在裝置螢幕的頂部或底部。它在使用者與應用程式互動時持續顯示於畫面上，並可在一段時間後自動重新整理。

本指南以錨定自適應 Banner 廣告（anchored adaptive banner）為起點。詳見 anchored adaptive banner ads。

錨定自適應 Banner 是固定長寬比（而非固定尺寸）的廣告，長寬比類似 320x50。指定可用的全寬後，Google Mobile Ads Flutter Plugin 會回傳該寬度下的最佳高度；最佳高度在不同廣告請求之間保持一致，重新整理時周圍內容不會位移。

大型自適應 Banner 提供更大的格式，設計用於非捲動佈局。相較於標準錨定自適應 Banner，允許更高的最大高度（最多螢幕高度的 20%，介於 50–150 dp），增加的空間針對影片內容最佳化。

務必使用測試廣告

建置與測試應用程式時，務必使用測試廣告而非正式廣告。否則可能導致帳號遭停權。

Banner 專用的測試廣告單元 ID：

Android：ca-app-pub-3940256099942544/9214589741
iOS：    ca-app-pub-3940256099942544/2435281174

測試廣告單元會對每個請求回傳測試廣告，可在撰寫、測試與除錯期間自由使用。發布應用程式前務必替換為自己的廣告單元 ID。

取得廣告尺寸

為請求正確尺寸的 Banner 廣告，請依下列步驟：

  1. 使用 MediaQuery.of(context) 取得裝置螢幕寬度（以密度無關像素 dp 計）。若不想使用全螢幕寬度，可自行設定寬度。
  2. 使用 AdSize 類別的適當靜態方法取得 AdSize 物件。例如使用 AdSize.getLargeAnchoredAdaptiveBannerAdSize(int width) 取得目前方向的廣告尺寸。
// 載入廣告前先取得 AnchoredAdaptiveBannerAdSize。
final size = await AdSize.getLargeAnchoredAdaptiveBannerAdSize(
  MediaQuery.sizeOf(context).width.truncate(),
);

載入廣告

以下範例載入一個 Banner 廣告：

void _loadAd() async {
  // 載入廣告前先取得 AnchoredAdaptiveBannerAdSize。
  final size = await AdSize.getLargeAnchoredAdaptiveBannerAdSize(
    MediaQuery.sizeOf(context).width.truncate(),
  );

  if (size == null) {
    // 無法取得錨定 Banner 的寬度。
    return;
  }

  unawaited(
    BannerAd(
      adUnitId: "_adUnitId",
      request: const AdRequest(),
      size: size,
      listener: BannerAdListener(
        onAdLoaded: (ad) {
          // 廣告成功接收時呼叫。
          debugPrint('Ad was loaded.');
          setState(() {
            _bannerAd = ad as BannerAd;
          });
        },
        onAdFailedToLoad: (ad, err) {
          // 廣告請求失敗時呼叫。
          debugPrint('Ad failed to load with error: $err');
          ad.dispose();
        },
      ),
    ).load(),
  );
}

將 _adUnitId 替換為自己的廣告單元 ID。

Banner 廣告事件

透過 BannerAdListener 可監聽生命週期事件，例如廣告載入完成。以下範例實作各方法並記錄訊息：

onAdOpened: (Ad ad) {
  // 廣告開啟覆蓋螢幕的 overlay 時呼叫。
  debugPrint('Ad was opened.');
},
onAdClosed: (Ad ad) {
  // 廣告移除覆蓋螢幕的 overlay 時呼叫。
  debugPrint('Ad was closed.');
},
onAdImpression: (Ad ad) {
  // 廣告產生曝光時呼叫。
  debugPrint('Ad recorded an impression.');
},
onAdClicked: (Ad ad) {
  // 發生點擊事件時呼叫。
  debugPrint('Ad was clicked.');
},
onAdWillDismissScreen: (Ad ad) {
  // 僅 iOS。關閉全螢幕檢視前呼叫。
  debugPrint('Ad will be dismissed.');
},

重新整理廣告

若在 AdMob UI 中設定廣告單元重新整理，廣告載入失敗時無需再次請求；Google Mobile Ads Flutter Plugin 會遵守 AdMob UI 指定的重新整理率。若未啟用重新整理，則需發出新請求。詳見 Use automatic refresh for Banner ads。

注意：在 AdMob UI 設定重新整理率時，自動重新整理僅在 Banner 於畫面上可見時才會發生。

顯示 Banner 廣告

要將 BannerAd 顯示為 widget，必須在呼叫 load() 之後，以支援的廣告實例化 AdWidget。可在呼叫 load() 前建立 widget，但 load() 必須在加入 widget tree 之前呼叫。

AdWidget 繼承自 Flutter 的 Widget 類別，可像其他 widget 一樣使用。在 iOS 上，務必將 widget 放置在指定寬度與高度的 widget 內，否則廣告可能無法顯示。BannerAd 可放在尺寸與廣告相符的容器中：

if (_bannerAd != null)
  Align(
    alignment: Alignment.bottomCenter,
    child: SafeArea(
      child: SizedBox(
        width: _bannerAd!.size.width.toDouble(),
        height: _bannerAd!.size.height.toDouble(),
        child: AdWidget(ad: _bannerAd!),
      ),
    ),
  ),

當不再需要存取廣告時，必須呼叫 dispose() 釋放。呼叫 dispose() 的最佳時機：在 AdWidget 從 widget tree 移除之後，或在 BannerAdListener.onAdFailedToLoad() 回呼中。

完成！應用程式現在已可顯示 Banner 廣告。

其他 Banner 類型

熟悉本節定義的其他 Banner 類型，以用於 Flutter 應用程式：

  • Inline adaptive banners：高度可變、相較於錨定自適應 Banner 更大、更高的 Banner；建議用於將 Banner 廣告放置於可捲動內容的應用程式。詳見 inline adaptive banners。
  • Collapsible banners：最初以較大的 overlay 呈現、提供按鈕可收合為較小尺寸的 Banner 廣告；可進一步最佳化成效。詳見 collapsible banner ads。

Interstitial 廣告

Interstitial 廣告是全螢幕廣告，覆蓋其主機應用程式的介面。通常顯示於應用程式流程的自然轉換點，例如活動之間或遊戲關卡之間的暫停。應用程式顯示插屏廣告時，使用者可選擇點擊廣告前往目的地，或關閉廣告返回應用程式。

本指南說明如何將插屏廣告整合至 Flutter 應用程式。

務必使用測試廣告

建置與測試應用程式時，務必使用測試廣告而非正式廣告。插屏專用的測試廣告單元 ID：

Android：ca-app-pub-3940256099942544/1033173712
iOS：    ca-app-pub-3940256099942544/4411468910

載入廣告

InterstitialAd.load(
  adUnitId: "_adUnitId",
  request: const AdRequest(),
  adLoadCallback: InterstitialAdLoadCallback(
    onAdLoaded: (InterstitialAd ad) {
      // 廣告成功接收時呼叫。
      debugPrint('Ad was loaded.');
      // 保留廣告參考以便稍後顯示。
      _interstitialAd = ad;
    },
    onAdFailedToLoad: (LoadAdError error) {
      // 廣告請求失敗時呼叫。
      debugPrint('Ad failed to load with error: $error');
    },
  ),
);

將 _adUnitId 替換為自己的廣告單元 ID。

Interstitial 廣告事件

透過 FullScreenContentCallback 可監聽生命週期事件，例如廣告顯示或關閉。顯示廣告前設定 InterstitialAd.fullScreenContentCallback 以接收通知。以下範例實作各方法：

ad.fullScreenContentCallback = FullScreenContentCallback(
  onAdShowedFullScreenContent: (ad) {
    // 廣告顯示全螢幕內容時呼叫。
    debugPrint('Ad showed full screen content.');
  },
  onAdFailedToShowFullScreenContent: (ad, err) {
    // 廣告無法顯示全螢幕內容時呼叫。
    debugPrint('Ad failed to show full screen content with error: $err');
    // 釋放資源。
    ad.dispose();
  },
  onAdDismissedFullScreenContent: (ad) {
    // 廣告關閉全螢幕內容時呼叫。
    debugPrint('Ad was dismissed.');
    // 釋放資源。
    ad.dispose();
  },
  onAdImpression: (ad) {
    // 廣告產生曝光時呼叫。
    debugPrint('Ad recorded an impression.');
  },
  onAdClicked: (ad) {
    // 記錄點擊時呼叫。
    debugPrint('Ad was clicked.');
  },
);

顯示 Interstitial 廣告

InterstitialAd 以 Overlay 顯示於所有應用程式內容之上並靜態放置，因此無法加入 Flutter widget tree。呼叫 show() 選擇顯示時機：

_interstitialAd?.show();

呼叫 show() 後，以此方式顯示的廣告無法以程式方式關閉，需使用者輸入。一個 InterstitialAd 只能顯示一次；後續呼叫 show 會觸發 onAdFailedToShowFullScreenContent。

當不再需要存取廣告時，必須呼叫 dispose() 釋放。呼叫 dispose() 的最佳時機：在 FullScreenContentCallback.onAdDismissedFullScreenContent 與 FullScreenContentCallback.onAdFailedToShowFullScreenContent 回呼中。

完成！應用程式現在已可顯示插屏廣告。

Native 廣告

Native 廣告是以平台原生 UI 元件向使用者呈現的廣告資產。在程式碼層面，當 native ad 載入時，應用程式會收到一個 NativeAd 物件，包含其資產；應用程式（而非 Google Mobile Ads Flutter Plugin）負責顯示它們。

此廣告格式適用於需要更多控制來設定廣告外觀的場景。若不需要這些功能，請使用其他廣告格式。

在 Flutter 應用程式中顯示 native ads 有兩種方式：

  • Native templates：使用 Dart API 樣式化的預定義 native templates。
  • Platform setup：使用 Android 與 iOS 版面工具定義的自訂平台特定版面。

Native templates

有兩種模板類型可選：small 或 medium。每種模板都有 UI 樣式選項，但自訂程度低於 platform setup 實作。

詳見 Native templates。

Platform setup

當需要對 Android 與 iOS 兩個平台的廣告外觀與風格擁有完整控制時，platform setup 更適合，但需要為兩個平台撰寫程式碼。

詳見 Platform setup。

顯示廣告

RewardedAd 以 Overlay 顯示於所有應用程式內容之上並靜態放置，因此無法加入 Flutter widget tree。呼叫 show() 選擇顯示時機。RewardedAd.show() 接受一個 OnUserEarnedRewardCallback，在使用者獲得獎勵時呼叫。務必實作並獎勵使用者：

_rewardedAd?.show(
  onUserEarnedReward: (AdWithoutView ad, RewardItem rewardItem) {
    debugPrint('Reward amount: ${rewardItem.amount}');
  },
);

呼叫 show() 後，以此方式顯示的廣告無法以程式方式關閉，需使用者輸入。一個 RewardedAd 只能顯示一次；後續呼叫 show 會觸發 onAdFailedToShowFullScreenContent。

伺服器端驗證（SSV）回呼（可選）

需要在 server-side verification 回呼中加入額外資料的應用程式，可使用 rewarded ads 的自訂資料功能。設定在 rewarded ad 物件上的任何字串值都會傳遞到 SSV 回呼的 custom_data 查詢參數。若未設定自訂資料值，SSV 回呼中將不會出現 custom_data 查詢參數。

RewardedAd.load(
  adUnitId: "_adUnitId",
  request: AdRequest(),
  rewardedAdLoadCallback: RewardedAdLoadCallback(
    onAdLoaded: (ad) {
      ServerSideVerificationOptions _options =
        ServerSideVerificationOptions(
          customData: 'SAMPLE_CUSTOM_DATA_STRING',
        );
      ad.setServerSideOptions(_options);
      _rewardedAd = ad;
    },
    onAdFailedToLoad: (error) {},
  ),
);

將 SAMPLE_CUSTOM_DATA_STRING 替換為自訂資料。

完整範例請見 API demo。

Rewarded interstitial 廣告

Rewarded interstitial 是一種獎勵廣告格式，可在應用程式自然轉換期間自動顯示廣告並提供獎勵。與 rewarded ads 不同，使用者無需選擇加入即可觀看 rewarded interstitial。本指南說明如何將 AdMob rewarded interstitial ads 整合進 Flutter 應用程式。

前置需求

  • 安裝 Flutter plugin 1.1.0 或更高版本
  • Set up Google Mobile Ads Flutter Plugin：Flutter 應用程式必須已匯入 Google Mobile Ads Flutter Plugin

務必使用測試廣告

Rewarded interstitial 專用的測試廣告單元 ID：

Android：ca-app-pub-3940256099942544/5354046379
iOS：    ca-app-pub-3940256099942544/6978759866

載入廣告

RewardedInterstitialAd.load(
  adUnitId: "_adUnitId",
  request: const AdRequest(),
  rewardedInterstitialAdLoadCallback: RewardedInterstitialAdLoadCallback(
    onAdLoaded: (RewardedInterstitialAd ad) {
      // 廣告成功接收時呼叫。
      debugPrint('Ad was loaded.');
      // 保留廣告參考以便稍後顯示。
      _rewardedInterstitialAd = ad;
    },
    onAdFailedToLoad: (LoadAdError error) {
      // 廣告請求失敗時呼叫。
      debugPrint('Ad failed to load with error: $error');
    },
  ),
);

將 _adUnitId 替換為自己的廣告單元 ID。

Rewarded interstitial 廣告事件

透過 FullScreenContentCallback 可監聽生命週期事件。以下範例實作各方法：

ad.fullScreenContentCallback = FullScreenContentCallback(
  onAdShowedFullScreenContent: (ad) {
    // 廣告顯示全螢幕內容時呼叫。
    debugPrint('Ad showed full screen content.');
  },
  onAdFailedToShowFullScreenContent: (ad, err) {
    // 廣告無法顯示全螢幕內容時呼叫。
    debugPrint('Ad failed to show full screen content with error: $err');
    // 釋放資源。
    ad.dispose();
  },
  onAdDismissedFullScreenContent: (ad) {
    // 廣告關閉全螢幕內容時呼叫。
    debugPrint('Ad was dismissed.');
    // 釋放資源。
    ad.dispose();
  },
  onAdImpression: (ad) {
    // 廣告產生曝光時呼叫。
    debugPrint('Ad recorded an impression.');
  },
  onAdClicked: (ad) {
    // 記錄點擊時呼叫。
    debugPrint('Ad was clicked.');
  },
);

顯示廣告

Key Point：顯示 rewarded interstitial 廣告給使用者之前，必須先呈現介紹畫面，提供清楚的獎勵訊息並允許使用者在廣告開始前跳過。詳見 Learn more。

RewardedInterstitialAd 以 Overlay 顯示於所有應用程式內容之上並靜態放置，因此無法加入 Flutter widget tree。呼叫 show() 選擇顯示時機。RewardedInterstitialAd.show() 接受一個 OnUserEarnedRewardCallback，在使用者獲得獎勵時呼叫。務必實作並獎勵使用者：

_rewardedInterstitialAd?.show(
  onUserEarnedReward: (AdWithoutView ad, RewardItem rewardItem) {
    debugPrint('Reward amount: ${rewardItem.amount}');
  },
);

呼叫 show() 後，以此方式顯示的廣告無法以程式方式關閉，需使用者輸入。一個 RewardedInterstitialAd 只能顯示一次；後續呼叫 show 會觸發 onAdFailedToShowFullScreenContent。

當不再需要存取廣告時，必須呼叫 dispose() 釋放。呼叫 dispose() 的最佳時機：在 FullScreenContentCallback.onAdDismissedFullScreenContent 與 FullScreenContentCallback.onAdFailedToShowFullScreenContent 回呼中。

伺服器端驗證（SSV）回呼（可選）

需要在 server-side verification 回呼中加入額外資料的應用程式，可使用 rewarded ads 的自訂資料功能。設定在 rewarded ad 物件上的任何字串值都會傳遞到 SSV 回呼的 custom_data 查詢參數。

RewardedInterstitialAd.load(
  adUnitId: "_adUnitId",
  request: AdRequest(),
  rewardedInterstitialAdLoadCallback: RewardedInterstitialAdLoadCallback(
    onAdLoaded: (ad) {
      ServerSideVerificationOptions _options =
        ServerSideVerificationOptions(
          customData: 'SAMPLE_CUSTOM_DATA_STRING',
        );
      ad.setServerSideOptions(_options);
      _rewardedInterstitialAd = ad;
    },
    onAdFailedToLoad: (error) {},
  ),
);

將 SAMPLE_CUSTOM_DATA_STRING 替換為自訂資料。

完整範例請見 API demo。

App open 廣告

App open 廣告是一種特殊廣告格式，供希望變現應用程式載入畫面的發佈商使用。App open 廣告可隨時關閉，設計用於使用者將應用程式帶到前景時顯示。

App open 廣告會自動顯示小型品牌區域，讓使用者知道仍在您的應用程式中。

前置需求

  • 安裝 Flutter plugin 0.13.6 或更高版本
  • Set up Google Mobile Ads Flutter Plugin：Flutter 應用程式必須已匯入 Google Mobile Ads Flutter Plugin

務必使用測試廣告

App open 專用的測試廣告單元 ID：

Android：ca-app-pub-3940256099942544/9257395921
iOS：    ca-app-pub-3940256099942544/5575463023

實作步驟

整合 app open ads 的主要步驟：

  1. 建立工具類別，在需要顯示前提前載入廣告。
  2. 載入廣告。
  3. 註冊回呼並顯示廣告。
  4. 訂閱 AppStateEventNotifier.appStateStream，在前景事件時顯示廣告。

顯示廣告與全螢幕回呼

顯示廣告前，為每個要監聽的廣告事件註冊 FullScreenContentCallback：

void showAdIfAvailable() {
  if (!isAdAvailable) {
    print('Tried to show ad before available.');
    loadAd();
    return;
  }
  if (_isShowingAd) {
    print('Tried to show ad while already showing an ad.');
    return;
  }
  // Set the fullScreenContentCallback and show the ad.
  _appOpenAd!.fullScreenContentCallback = FullScreenContentCallback(
    onAdShowedFullScreenContent: (ad) {
      _isShowingAd = true;
      print('$ad onAdShowedFullScreenContent');
    },
    onAdFailedToShowFullScreenContent: (ad, error) {
      print('$ad onAdFailedToShowFullScreenContent: $error');
      _isShowingAd = false;
      ad.dispose();
      _appOpenAd = null;
    },
    onAdDismissedFullScreenContent: (ad) {
      print('$ad onAdDismissedFullScreenContent');
      _isShowingAd = false;
      ad.dispose();
      _appOpenAd = null;
      loadAd();
    },
  );
}

監聽前景事件

    if (appState == AppState.foreground) {
      appOpenAdManager.showAdIfAvailable();
    }
  }
}

廣告過期

Key Point：App open beta 中的廣告參考將在四小時後逾時。請求時間四小時後呈現的廣告將不再有效，可能無法賺取收益。此時間限制正在審慎考慮中，未來 beta 版本的 app open 格式可能會變更。

為確保不顯示過期廣告，請在 AppOpenAdManager 加入時間戳記，以檢查廣告載入後經過的時間。然後使用該時間戳記判斷廣告是否仍有效：

class AppOpenAdManager {
  ...
  /// 載入與顯示廣告之間允許的最長持續時間。
  final Duration maxCacheDuration = Duration(hours: 4);
  /// 記錄載入時間，避免顯示過期廣告。
  DateTime? _appOpenLoadTime;
  ...

  void loadAd() {
    AppOpenAd.load(
      adUnitId: adUnitId,
      orientation: AppOpenAd.orientationPortrait,
      adRequest: AdRequest(),
      adLoadCallback: AppOpenAdLoadCallback(
        onAdLoaded: (ad) {
          print('$ad loaded');
          _appOpenLoadTime = DateTime.now();
          _appOpenAd = ad;
        },
        onAdFailedToLoad: (error) {
          print('AppOpenAd failed to load: $error');
        },
      ),
    );
  }

  void showAdIfAvailable() {
    if (!isAdAvailable) {
      print('Tried to show ad before available.');
      loadAd();
      return;
    }
    if (_isShowingAd) {
      print('Tried to show ad while already showing an ad.');
      return;
    }
    if (DateTime.now().subtract(maxCacheDuration).isAfter(_appOpenLoadTime!)) {
      print('Maximum cache duration exceeded. Loading another ad.');
      _appOpenAd!.dispose();
      _appOpenAd = null;
      loadAd();
      return;
    }
    // Set the fullScreenContentCallback and show the ad.
    _appOpenAd!.fullScreenContentCallback = FullScreenContentCallback(...);
    _appOpenAd!.show();
  }
}

冷啟動與載入畫面

至此文件皆假設僅在使用者將應用程式帶到前景（應用程式先前已暫停於記憶體中）時顯示 app open ads。「冷啟動」發生於應用程式啟動但先前未暫停於記憶體中。

冷啟動的範例是使用者首次開啟應用程式。冷啟動時，不會有先前已載入並可立即顯示的 app open ad。請求廣告與收到廣告之間的延遲可能造成使用者在被意外的不相關廣告打斷前短暫使用應用程式，應避免此不良使用者體驗。

冷啟動時使用 app open ads 的首選方式是使用載入畫面載入遊戲或應用程式資產，並僅從載入畫面顯示廣告。若應用程式已完成載入並已將使用者送至主要內容，請勿顯示廣告。

Key Point：為在顯示 app open 廣告期間繼續載入應用程式資產，務必在背景執行緒載入資產。

最佳實踐

App open ads 有助於在應用程式首次啟動與應用程式切換時變現載入畫面，但請記住最佳實踐以確保使用者享受使用應用程式：

  • 在使用者使用應用程式數次後再顯示第一個 app open ad。
  • 在使用者原本會等待應用程式載入的時機顯示 app open ads。
  • 若 app open ad 下方有載入畫面，且載入畫面在廣告關閉前完成載入，可在 onAdDismissedFullScreenContent 事件處理器中關閉載入畫面。

當廣告載入失敗時，會呼叫失敗回呼並提供一個 LoadAdError 物件。

以下程式碼片段示範 rewarded ad 載入失敗時如何取得錯誤資訊：

onAdFailedToLoad: (ad, loadAdError) {
  // 取得錯誤來源的網域。
  String domain = loadAdError.domain;

  // 取得錯誤代碼。請參閱
  // https://developers.google.com/admob/android/reference/com/google/android/gms/ads/AdRequest
  // 與 https://developers.google.com/admob/ios/api/reference/Enums/GADErrorCode
  // 以取得可能的代碼清單。
  int code = loadAdError.code;

  // 方便記錄的字串，摘要錯誤。
  String message = loadAdError.message;

  // 取得回應資訊，可能包含 mediation 請求的結果。
  ResponseInfo? responseInfo = loadAdError.responseInfo;
}

此資訊可用於更準確地判斷廣告載入失敗的原因。特別是對於 iOS 上網域 com.google.admob 與 Android 上網域 com.google.android.gms.ads 的錯誤，可查閱 此說明中心文章 以取得更詳細的說明與可能的解決動作。

ResponseInfo 的屬性包括：

屬性說明

loadedAdapterResponseInfo回傳載入廣告的 adapter 對應的 AdapterResponseInfo。
mediationAdapterClassName回傳載入廣告的廣告網路的 mediation adapter 類別名稱。

伺服器端驗證（SSV）

Server-side verification 回呼是 URL 請求，由 Google 發送給外部系統，通知其使用者應因與 rewarded 或 rewarded interstitial 廣告互動而獲得獎勵。Rewarded SSV 提供額外保護層，防止偽造客戶端回呼以獎勵使用者。

本指南說明如何使用 Tink Java Apps 第三方密碼學函式庫驗證 rewarded SSV 回呼，以確保回呼中的查詢參數為合法值。雖然本指南使用 Tink，但也可使用任何支援 ECDSA 的第三方函式庫。也可使用 AdMob UI 中的測試工具測試伺服器。

Key Point：本指南並非意圖展示每種語言的伺服器端回呼驗證範例。若不熟悉將這些概念應用於所選的 ECDSA 函式庫，建議使用 Google Mobile Ads SDK 的客戶端獎勵回呼來獎勵使用者。

        RewardedAdsVerifier.KEYS_DOWNLOADER_INSTANCE_PROD)
    .build();

verifier.verify(rewardUrl);

Rewarding the user

決定何時獎勵使用者時，平衡使用者體驗與獎勵驗證非常重要。Server-side callbacks 可能在到達外部系統前延遲。因此，建議使用客戶端回呼立即獎勵使用者，同時在收到 server-side callbacks 時對所有獎勵進行驗證。此方法提供良好使用者體驗，同時確保授予獎勵的有效性。

然而，對於獎勵有效性至關重要（例如獎勵影響應用程式遊戲經濟）且延遲授予獎勵可接受的應用程式，等待已驗證的 server-side callback 可能是最佳方法。

Custom data

需要在 server-side verification 回呼中加入額外資料的應用程式，可使用 rewarded ads 的自訂資料功能。設定在 rewarded ad 物件上的任何字串值都會傳遞到 SSV 回呼的 custom_data 查詢參數。若未設定自訂資料值，SSV 回呼中將不會出現 custom_data 查詢參數。

若要設定自訂獎勵字串，必須在顯示廣告前設定。

Key Point：自訂獎勵字串會被 percent-escaped，解析 SSV 回呼時可能需要解碼。
RewardedAd.load(
  adUnitId: "_adUnitId",
  request: AdRequest(),
  rewardedAdLoadCallback: RewardedAdLoadCallback(
    onAdLoaded: (ad) {
      ServerSideVerificationOptions _options =
        ServerSideVerificationOptions(
          customData: 'SAMPLE_CUSTOM_DATA_STRING',
        );
      ad.setServerSideOptions(_options);
      _rewardedAd = ad;
    },
    onAdFailedToLoad: (error) {},
  ),
);

將 SAMPLE_CUSTOM_DATA_STRING 替換為自訂資料。

FAQ

  • 可以快取 AdMob key server 提供的公鑰嗎？ 建議快取以減少驗證 SSV 回呼所需的作業。但公鑰會定期輪換，快取時間不應超過 24 小時。
  • 公鑰輪換頻率為何？ 輪換排程不定。為確保 SSV 回呼驗證持續正常，公鑰快取不應超過 24 小時。
  • 伺服器無法連線時會發生什麼？ Google 期待 HTTP 200 OK 成功狀態回應。若伺服器無法連線或未提供預期回應，Google 將以一秒間隔重試最多五次。
  • 如何驗證 SSV 回呼來自 Google？ 使用反向 DNS 查詢驗證 SSV 回呼源自 Google。

WebView API for Ads

WebView API for Ads 允許使用 WebViewController 進行應用程式內廣告變現。若應用程式透過 WebViewController 顯示使用 AdSense code 或 Google Publisher Tag 實作廣告的網頁內容，應使用此 API 啟用廣告變現。詳見 AdMob policies。

兩種變現路徑

  1. 透過 Google Mobile Ads Flutter Plugin 請求廣告變現：可透過 Google Mobile Ads Flutter Plugin 向 AdMob 請求廣告，實作行動應用程式廣告格式來變現應用程式。詳見 匯入外掛。
  2. 使用 WebView API for Ads：若應用程式使用 WebViewController 顯示來自 Ad Manager 或 AdSense 的廣告網頁內容，使用 WebView API for Ads 註冊 WebViewController 物件。JavaScript 在 AdSense code 或 Google Publisher Tag 中建構並發送廣告請求，無需 SDK 請求。注意僅 mobile web 與 desktop web inventory formats 可透過此 API 使用。若不擁有 WebViewController 中的網頁內容，仍建議使用此 API 以保護廣告商免受垃圾內容影響，並提升提供內容的網頁發佈商變現。

兩種方式可擇一使用，或在同一應用程式中同時使用。

Before you begin

  • 使用 Google Mobile Ads Flutter Plugin 3.0.0 或更高版本。
  • 在 pubspec.yaml 加入 webview_flutter 相依。
  • 在應用程式中加入 webview_flutter_android 3.7.0 或更高版本。

<meta-data

<!-- Bypass GADApplicationIdentifier check for WebView API for Ads -->

<string>webview</string>

Register the WebViewController

為提升 WebViewController 中使用 AdSense code 或 Google Publisher Tags 的廣告變現，請依下列步驟：

  1. 在 WebViewController 啟用 JavaScript。否則廣告可能無法載入。
  2. 為提升使用者廣告體驗並與 Chrome 的 cookie 政策一致，在 AndroidWebViewController 實例啟用第三方 cookies。
  3. 呼叫 Google Mobile Ads Flutter Plugin 提供的 registerWebView() 方法註冊 WebViewController 實例。
import 'package:google_mobile_ads/google_mobile_ads.dart';
import 'package:webview_flutter/webview_flutter.dart';
import 'package:webview_flutter_android/webview_flutter_android.dart';

@override
class WebViewExampleState extends State<WebViewExample> {
  late final WebViewController controller;

  @override
  void initState() {
    super.initState();
    createWebView();
  }

  void createWebView() async {
    controller = WebViewController();
    // 1. Enable JavaScript in the web view.
    await controller.setJavaScriptMode(JavaScriptMode.unrestricted);
    // 2. Enable third-party cookies for Android.
    if (controller.platform is AndroidWebViewController) {
      AndroidWebViewCookieManager cookieManager = AndroidWebViewCookieManager(
        const PlatformWebViewCookieManagerCreationParams());
      await cookieManager.setAcceptThirdPartyCookies(
        controller.platform as AndroidWebViewController, true);
    }
    // 3. Register the web view.
    await MobileAds.instance.registerWebView(controller);
  }
}

測試廣告

本指南說明如何在廣告整合中啟用測試廣告。開發期間啟用測試廣告非常重要，以便點擊廣告而不向 Google 廣告商收費。若在非測試模式下點擊過多廣告，帳號可能被標記為無效活動。

取得測試廣告有兩種方式：

  1. 使用 Google 的 sample ad units。
  2. 使用自己的廣告單元並啟用測試裝置。

前置需求

  • Set up Google Mobile Ads Flutter Plugin。
  • Import Google Mobile Ads Flutter Plugin 至 Flutter 應用程式。

Sample ad units

啟用測試最快的方式是使用 Google 提供的測試廣告單元。這些廣告單元不與 AdMob 帳號關聯，因此使用時帳號不會產生無效流量。

Google 為 Android 與 iOS 提供不同的測試廣告單元。在 iOS 上進行測試請求需使用 iOS 測試廣告單元，在 Android 上需使用 Android 測試廣告單元。

這些廣告單元指向特定的測試 creatives。

Key Point：發布應用程式前務必將這些測試 ID 替換為自己的廣告單元 ID。

啟用測試裝置

若想以更接近正式的廣告進行更嚴謹的測試，可將裝置設定為測試裝置並使用在 AdMob UI 建立的廣告單元 ID。

Key Point：Android emulators 與 iOS simulators 會自動設定為測試裝置。

在 AdMob UI 加入測試裝置

使用 AdMob UI 以簡單、非程式化的方式加入測試裝置並測試新的或現有的應用程式建置。詳見 Learn how。

Key Point：新測試裝置通常在 15 分鐘內開始在應用程式中投放測試廣告，但最多可能需要 24 小時。

使用應用程式層級測試模式

指定要測試的應用程式與版本並接收測試廣告，使用應用程式層級測試模式。詳見 Set up a test app。

Mediation 測試

Google 的 sample ad units 只顯示 Google Ads。要測試 mediation 設定，必須啟用測試裝置。

Mediated ads 不會顯示 Test Ad 標籤。您有責任確保每個 mediation 網路的測試廣告已啟用，以免這些網路將帳號標記為無效活動。詳見各網路的 mediation 指南。

若不確定某個 mediation 廣告網路 adapter 是否支援測試廣告，開發期間最安全的做法是避免點擊該網路的廣告。可檢查任何廣告格式的 Ad.responseInfo 以判斷目前廣告由哪個廣告網路提供。
